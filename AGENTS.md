# Правила работы с репозиторием

Документ для агентов и людей: как вести изменения в этом проекте. Коротко и по делу.

## Запрос на PR = коммит и PR без дополнительных подтверждений

Если прозвучала просьба «сделай PR», «открой PR», «создай пулл-реквест» (в любой формулировке),
всё делается сразу, одним заходом, без уточняющих вопросов:

1. Проверить, что изменения готовы: прогнать тесты (`.venv/bin/python -m pytest -q` из `stocrm-agent`),
   `pip check`, `git diff --check`.
2. Добавить в индекс файлы именно этой задачи (`git add <файлы>`), не подметая чужие правки.
3. Сделать коммит с осмысленным сообщением: что исправлено и почему.
4. Отправить ветку: `git push origin <текущая рабочая ветка>`.
5. Открыть PR из рабочей ветки в `main` через `gh pr create` и в описании указать:
   что исправлено, что проверено только на имитациях, какие остаются ограничения.
6. Ответить пользователю ссылкой на PR и списком проверок.

Если коммитить нечего (дерево чистое), но ветка впереди `main` — просто запушить и открыть PR.
Если пушить нечего и PR уже есть — сказать об этом и дать ссылку.

## Границы

- Работать только в ветке текущей сессии; не пушить в другие ветки и не создавать новые без просьбы.
- Мержить, закрывать PR, деплоить и публиковать — только по отдельной явной просьбе.
- Секреты (`.env`, `.state`, ключи, токены) не читать, не выводить и не коммитить.
- Реальных записей в рабочую CRM при отладке не делать: проверка на имитациях и тестах.
- Не удалять пользовательские изменения и данные состояния; незакоммиченные правки не откатывать.

## Без запроса на PR

Изменения остаются в рабочем дереве: не коммитить, не пушить, не открывать PR.
В ответе перечислить, что изменено и какие проверки пройдены.
