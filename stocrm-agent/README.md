# STOCRM-агент

**Помощник для работы с автосервисом в STOCRM — из Telegram или через MCP.**

Просматривайте сделки и календарь, находите клиентов и запчасти, готовьте изменения текстом или голосом. Бот работает на вашем компьютере и обращается к вашей панели STOCRM.

`Python` · `Telegram` · `STOCRM API` · `MCP` · **Версия кода: 140**

> **Начните с безопасного режима.** Оставьте подтверждение изменений включённым, проверяйте черновики перед применением и ограничьте доступ к боту своими Telegram ID. При включённом авторежиме действия, разрешённые политикой, могут выполняться без дополнительной кнопки.

## Возможности

| Раздел | Что умеет агент |
|---|---|
| **Сделки** | Показывает карточки и списки по статусам, работы, товары, сумму и проверенный долг. Сделку из списка можно открыть кнопкой. |
| **Календарь** | Показывает записи за выбранный день с учётом часового пояса подразделения; помогает подготовить запись клиента. |
| **Клиенты и автомобили** | Ищет контакты и связанные данные, помогает подготовить создание клиента и изменение карточки. |
| **Работы и запчасти** | Помогает подобрать и добавить позиции, запрашивает недостающие данные. Бренд и применяемость нужно проверять. |
| **Поставщики** | Опциональный поиск брендов через Росско и Профит Лигу. Заказы поставщикам через бота не отправляются. |
| **Текст и голос** | Принимает обычные сообщения и голосовые. Для сложных запросов использует языковую модель; для голосовых — распознавание речи. |
| **MCP** | Предоставляет инструменты STOCRM совместимому MCP-клиенту; Telegram для этого не обязателен. |

Доступные действия зависят от прав ключа STOCRM, настроек, API панели и политики подтверждений. В статусном списке показываются не более 25 сделок; при неполном чтении бот предупреждает об этом. Неизвестный долг **не означает нулевой**. Если данные важны для решения, сверьте их в CRM. Сохранение заметок в сделках сейчас отключено.

## Как это работает

```text
Сообщение или голосовое в Telegram
              ↓
      Бот на вашем компьютере
              ↓
   Чтение данных и подготовка действия
              ↓
   Черновик и подтверждение* → STOCRM
```

\* При включённых подтверждениях. В авторежиме действуют выбранные в `/settings` правила: разрешённая операция может быть отправлена без дополнительного подтверждения. Некоторые простые запросы на просмотр обрабатываются напрямую, без модели.

## Быстрый старт

Все действия ниже выполняются в папке **`stocrm-agent`**: в ней находятся `setup.bat`, `start_bot.bat` и `requirements.txt`.

### Что понадобится

- Python **3.12 или 3.13** и интернет-доступ к используемым сервисам.
- Домен панели и API-ключ STOCRM; бот Telegram и свой Telegram ID.
- Провайдер языковой модели; для голосовых — также провайдер распознавания речи. В шаблоне используются Google AI Studio и Groq; условия и лимиты зависят от аккаунта.
- На Windows при установке Python отметьте **Add python.exe to PATH**.

### Windows

1. Скачайте проект или распакуйте архив целиком. Откройте папку `stocrm-agent` — не запускайте файлы прямо из ZIP.
2. Дважды нажмите **`setup.bat`** и следуйте мастеру. Он создаст окружение и поможет заполнить локальные настройки.
3. Дважды нажмите **`start_bot.bat`**. Оставьте окно открытым: пока работает процесс, работает бот.
4. Откройте своего бота в Telegram, отправьте `/start` и проверьте связь с панелью через `/crm_test`.
5. В `/settings` проверьте, что подтверждения включены, а доступ ограничен нужными сотрудниками.

### Linux и macOS

Откройте терминал в папке `stocrm-agent` и выполните:

```bash
bash setup.sh
bash start_bot.sh
```

Мастер поможет настроить окружение и `.env`. Для остановки бота нажмите `Ctrl+C`. Подробности и альтернативная ручная настройка — в [инструкции по установке](docs/INSTALL.md).

> При запуске бот очищает ожидающие обновления Telegram (`drop_pending_updates`): накопившиеся до запуска сообщения и нажатия кнопок могут быть отброшены. Не запускайте одновременно две копии бота с одним токеном.

## Настройка

Мастер сохраняет настройки в локальный **`.env`**. Пример без ключей находится в [`.env.example`](.env.example).

| Параметр | Для чего нужен |
|---|---|
| `STOCRM_DOMAIN`, `STOCRM_SID` | Адрес панели и ключ API STOCRM. |
| `STOCRM_MOCK` | `0` — реальная CRM; `1` — имитация CRM. |
| `TG_BOT_TOKEN` | Токен вашего Telegram-бота. |
| `TG_ALLOWED_USERS`, `TG_ADMIN_USERS` | Telegram ID пользователей и администраторов. |
| `TG_CONFIRM_REQUIRED` | Начальная настройка подтверждений; действующая политика управляется через `/settings`. |
| `LLM_PROVIDER`, `LLM_API_KEY` | Провайдер модели и ключ, если он требуется. |
| `STT_PROVIDER`, `STT_API_KEY` | Провайдер и ключ распознавания речи, если они требуются. |
| `STOCRM_STATE_DIR` | Папка состояния; по умолчанию `.state`. |

`STOCRM_MOCK=1` заменяет только CRM имитацией: другие настроенные сервисы, например Telegram, модель или распознавание речи, всё равно могут использовать сеть. Для работы с реальной панелью проверьте `STOCRM_MOCK=0`.

Провайдеры модели и распознавания могут получать данные запросов и голосовые записи. Перед использованием проверьте их условия и свои права на передачу персональных данных. Варианты настройки описаны в [LLM](docs/LLM.md) и [настройке провайдеров](docs/SETUP_FREE.md).

## Примеры запросов

Напишите или надиктуйте боту:

```text
Покажи последние сделки
Покажи сделки в записи
Покажи ожидание оплаты
Покажи календарь на завтра
Покажи сделку 12345 подробно
Добавь в сделку 12345 работу диагностика за 950 рублей
```

Для неоднозначных запросов бот может попросить номер, воронку, статус, бренд или другие уточнения. «Эта сделка» относится к последней достоверно показанной сделке этого пользователя; явный номер имеет приоритет. При записи обязательно проверьте выбранную сделку и данные в черновике.

### Команды Telegram

| Команда | Назначение |
|---|---|
| `/start`, `/help` | Начало работы и справка. |
| `/settings` | Политика подтверждений по группам действий. |
| `/users` | Управление доступом сотрудников. |
| `/drafts` | Просмотр черновиков и их состояния. |
| `/staff` | Список сотрудников для выбора исполнителя. |
| `/crm_test` | Проверка связи со STOCRM — чтение, без записи. |
| `/voice_test` | Проверка распознавания речи. |
| `/balance_test НОМЕР` | Диагностика структуры ответа баланса сделки, без вывода сумм. |
| `/reset` | Сброс контекста диалога. |

Доступность отдельных команд зависит от прав пользователя.

## Безопасность

- **Проверяйте перед записью.** Сверяйте номер сделки, клиента, статус, дату, позиции, количество и цены. Ошибки распознавания речи и модели возможны.
- **Подтверждение зависит от политики.** В обычном режиме действие показывается черновиком; в авторежиме разрешённое действие может выполняться без дополнительной кнопки. Для MCP изменение применяется через подготовленный черновик.
- **Не повторяйте неопределённый результат.** При `partial`, обрыве или неизвестном исходе сначала проверьте CRM и `/drafts`. Не удаляйте `.state` и не повторяйте операцию вслепую: это может создать дубль.
- **Не делитесь секретами.** Не отправляйте `.env`, ключи API, токены и всю папку `.state` в чат или поддержку.
- **Сверяйте данные.** Запись в календарь и проверки перед ней не атомарны; другой сотрудник может изменить данные одновременно. Цвета статусов в Telegram приблизительные.
- **Проверяйте валюту.** Для полного поддерживаемого формата баланса с пустым названием валюты по умолчанию предполагается RUB. В многовалютной панели задайте `STOCRM_BALANCE_EMPTY_CURRENCY=STRICT`, чтобы отключить это допущение.

### Проверка записи на тестовой сделке

1. Создайте **новую тестовую сделку** в CRM и включите подтверждения в `/settings`.
2. Попросите добавить тестовую позицию с явными номером сделки, артикулом, брендом, количеством и ценой.
3. Проверьте черновик. Убедитесь, что до подтверждения запись не появилась в CRM, затем подтвердите **один раз**.
4. Откройте сделку в панели и сверьте позицию, количество, цену и отсутствие дубля.
5. Если результат частичный или неизвестный, не повторяйте запись: сначала проверьте CRM и состояние операции.

Используйте только тестовые данные и действия, на которые у вас есть разрешение.

## Обновление

1. Остановите старого бота и распакуйте новую версию в **новую папку**.
2. Перенесите собственные **`.env`** и **`.state`** из старой папки. Если в `.env` указаны абсолютные пути к состоянию, сохраните доступ к ним. Не переносите `.venv`.
3. Запустите `setup.bat` на Windows или `bash setup.sh` на Linux/macOS, затем запустите бота из новой папки.
4. Проверьте настройки и связь. Не удаляйте состояние ради повторной записи незавершённой операции.

## Диагностика

| Ситуация | Что проверить |
|---|---|
| Бот не отвечает | Открыто ли окно бота, правильный ли токен и разрешён ли ваш Telegram ID. |
| Нет связи с CRM | Выполните `/crm_test`; проверьте домен, ключ и права API. |
| Голосовое не распознано | Выполните `/voice_test`; проверьте настройки провайдера речи. |
| Не удалось проверить долг | Это не ноль. Проверьте сумму и оплаты в CRM; возможны тайм-аут или неподдержанный ответ API. |
| Частичный или неизвестный результат | Не повторяйте запись. Сначала сверьте фактическое состояние в CRM и `/drafts`. |

**Сколько это занимает места.** Полный экспорт — это все события бота, включая тела запросов и ответы панели. На диске журнал хранится как до десяти файлов по 10 МиБ, поэтому `support_log.txt` легко вырастает до десятков мегабайт, а отчёт `collect_report.bat` добавляет ещё 13 разделов, хвост `bot.log` в 1500 строк и 1200 событий аудита. Для одного случая такого объёма не нужно.

**Быстрый разбор одного случая.** Если известны время и (по возможности) номер сделки, запустите **`collect_incident.bat`** — он делает маленькую выжимку `incident.txt` за последние 45 минут, обычно десятки килобайт:

```bat
collect_incident.bat
collect_incident.bat --minutes 20 --offer 1371
```

В выжимке пять разделов: ошибки, что уходило в панель (записи и подтверждения), всё по указанной сделке, десять самых медленных вызовов CRM и чек-лист «что смотреть». Время можно задать явно — `--from "15:55"` или `--from "06.11 15:55" --to "06.11 16:05"`; если время указано без даты и ещё не наступило, берётся вчерашний день.

Если файл с журналом уже есть (например, `support_log.txt` с другого компьютера), разбирать можно прямо его, без папки `.state`:

```bash
.venv/bin/python -m stocrm_agent.cli support-incident --file support_log.txt --from "15:55" --to "16:05" --offer 1371
```

Время в окне трактуется по поясу самого журнала, а не того компьютера, где запущена команда. В строках видны `trace=…` и `draft=…`, поэтому две попытки записи и их черновики не путаются. Команда только читает локальные файлы: в сеть и в CRM ничего не отправляется. Если нужен полный журнал, на Windows запустите **`collect_log.bat`** и откройте созданный `support_log.txt`. На Linux/macOS из папки проекта можно выполнить:

```bash
.venv/bin/python -m stocrm_agent.cli support-incident --minutes 45
.venv/bin/python -m stocrm_agent.cli support-log
```

**Перед отправкой просмотрите файл.** Журнал может содержать имена, телефоны, данные сделок, фрагменты аргументов инструментов и коммерческую информацию. Известные секреты маскируются, но фильтр не безошибочен. Передавайте журнал только при наличии права на передачу данных; `.env`, сырые журналы и `.state` не отправляйте. При `truncated=true` часть данных сокращена.

## MCP и разработка

MCP-сервер работает по `stdio`. В настройках клиента укажите Python из окружения проекта, аргументы `-m stocrm_agent.server` и рабочую папку `stocrm-agent`. Не публикуйте конфигурацию с ключами. Подробнее — [установка MCP](docs/INSTALL.md#mcp-дополнительно-не-нужен-для-telegram).

Для локальных тестов установите зависимости проекта и `pytest` в виртуальное окружение. Из папки `stocrm-agent`:

```bash
python -m pytest -q
```

Тесты используют имитации. Их прохождение не подтверждает работу конкретной панели, Telegram, провайдера модели или Windows. В последней проверке версии 140 прошли 1137 тестов; без Git-репозитория два теста правил `.gitignore` нужно исключить.
